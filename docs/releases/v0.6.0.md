Kuberniva 0.6.0 adds a cluster topology map, an Argo CD application graph, Helm releases, an Open Cluster Management hub, and update checks from the menu bar.

## ✨ What's new

**Cluster topology**
- A new **Topology** page, right under **Overview**, maps how objects connect in the selected namespace or across the whole cluster
- Traffic reads left to right: Gateways and Ingresses → HTTPRoutes and GRPCRoutes → Services → Deployments, StatefulSets, DaemonSets, and CronJobs → ReplicaSets and Jobs → Pods
- Dashed lines show the ConfigMaps, Secrets, and PersistentVolumeClaims each workload uses; one shared by several apps appears in each of them
- Failing Pods, Services that select no Pods, and references to ConfigMaps or Secrets that do not exist are flagged in red, and the sidebar counts them
- **Problems only** and a filter narrow the map; busy ReplicaSets fold extra Pods into **+N pods**, with failing Pods always shown
- Click any object to open it; the map refreshes every 15 seconds
- Secrets are read as names only, so their values never leave the cluster

**Argo CD application graph**
- A new **Graph** tab draws each Application like the Argo CD dashboard: the app, its managed resources, and what they own, down to ReplicaSets, Pods, Jobs, and EndpointSlices
- Nodes are colored by health, and edges into degraded objects turn red
- Busy parents fold extra children into a **+N more** node; click it to expand
- Click a Pod to open its logs, or any managed resource to open its details
- The graph refreshes every 10 seconds while it is open

**Helm and Kustomize**
- A new **Helm** page lists every Helm release in the cluster or namespace, with chart, chart version, app version, revision, status, and last update
- Open a release for its **Values**, **Notes**, rendered **Manifest**, and **History**, and switch between revisions
- **Upgrade in CLI**, **Rollback in CLI**, and **History in CLI** prefill the matching `helm` command in the built-in terminal so you can review it before running
- Releases are read from Helm's own storage, so no `helm` binary is needed to browse them
- Argo CD Applications get a **Parameters** tab with each source's Helm values, value files, and parameters, or its Kustomize options (name prefix and suffix, namespace, common labels, replicas, components, patches, and more)

**Open Cluster Management**
- On an OCM hub, a new **OCM Hub** page shows managed clusters with availability, join and acceptance status, Kubernetes version, allocatable capacity, cluster claims, taints, and add-ons
- Tabs for **Cluster sets**, **Placements** (with the clusters each one selected), **ManifestWorks**, and **Policies** (with per-cluster compliance)
- The sidebar marks unavailable managed clusters, and the page updates live
- The page only appears on clusters that serve the OCM APIs, the same way Argo CD does

**Updates**
- **Kuberniva → Check for Updates…** now sits in the macOS menu bar, right under **About Kuberniva**
- When a new version is out, Kuberniva shows a dialog with its release notes on its own, at launch or during a quiet check every few hours, and asks only once per version

**Naming**
- **Custom APIs** in the sidebar is now **Custom Resources**, the Kubernetes term for objects defined by CRDs and aggregated APIs

## 🔄 Updating

- **In the app:** **Settings → Check for updates → Download and install → Restart now**
- **With Homebrew:** `brew upgrade --cask --greedy kuberniva`
- **New install:** `brew install --cask velqa/tap/kuberniva`, or download the DMG below

Runs natively on Apple Silicon and Intel Macs. Signed with an Apple Developer ID and notarized by Apple.
